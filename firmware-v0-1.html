HUD Firmware v0.1 - RPM First (ESP32-2432S024 + CAN)

Target: ESP32-2432S024 (2.4 inch, 240x320), Arduino IDE, wired CAN via SN65HVD230 transceiver. Car: 2011 Mercedes E350 (W212, M272). This first version does one job: read RPM from the car as fast and accurately as possible and show it big on screen.

Before you flash (read this)

  • I could not verify the exact pinout of your board (my web searches failed), so the CAN pins below are placeholders. Check your board's pin diagram for two free GPIOs before wiring. Do not wire the transceiver until you confirm the pins.

  • The screen needs a TFT_eSPI User_Setup file for this board. I will give you that in the next step once we confirm the pins and touch type.

  • Do not power the ESP32 from the OBD2 12V line directly. Use a 12V to 5V buck converter.

  • Wiring: OBD2 pin 6 = CAN High, pin 14 = CAN Low, pin 16 = 12V, pins 4 and 5 = ground. CAN H and CAN L go to the transceiver. Transceiver TX/RX go to the two ESP32 pins you choose.

How RPM polling works

  • Standard OBD2 request for RPM is Mode 01, PID 0C.

  • Send a CAN frame to ID 0x7DF with data: 02 01 0C 00 00 00 00 00.

  • The engine ECU replies on ID 0x7E8 with: 04 41 0C A B. RPM = ((A * 256) + B) / 4.

  • To keep updates fast, the code sends the next request as soon as a reply arrives, instead of waiting a fixed delay.

Code

#include <Arduino.h>
#include "driver/twai.h"

// ====== CHANGE THESE after checking your board's free pins ======
#define CAN_TX_PIN GPIO_NUM_22   // PLACEHOLDER
#define CAN_RX_PIN GPIO_NUM_27   // PLACEHOLDER
// ================================================================

float rpm = 0;
unsigned long lastRequest = 0;
bool waitingForReply = false;

void setupCAN() {
  twai_general_config_t g = TWAI_GENERAL_CONFIG_DEFAULT(CAN_TX_PIN, CAN_RX_PIN, TWAI_MODE_NORMAL);
  twai_timing_config_t t = TWAI_TIMING_CONFIG_500KBITS();  // standard OBD2 CAN speed
  twai_filter_config_t f = TWAI_FILTER_CONFIG_ACCEPT_ALL();
  if (twai_driver_install(&g, &t, &f) != ESP_OK) { Serial.println("CAN install failed"); return; }
  if (twai_start() != ESP_OK) { Serial.println("CAN start failed"); return; }
  Serial.println("CAN started");
}

void requestRPM() {
  twai_message_t m = {};
  m.identifier = 0x7DF;
  m.data_length_code = 8;
  m.data[0] = 0x02; m.data[1] = 0x01; m.data[2] = 0x0C;
  twai_transmit(&m, pdMS_TO_TICKS(10));
  lastRequest = millis();
  waitingForReply = true;
}

void readReplies() {
  twai_message_t m;
  while (twai_receive(&m, 0) == ESP_OK) {
    if (m.identifier == 0x7E8 && m.data[1] == 0x41 && m.data[2] == 0x0C) {
      rpm = ((m.data[3] * 256.0) + m.data[4]) / 4.0;
      waitingForReply = false;
    }
  }
}

void setup() {
  Serial.begin(115200);
  setupCAN();
}

void loop() {
  readReplies();
  // send next request right after a reply, or retry after 50 ms with no reply
  if (!waitingForReply || millis() - lastRequest > 50) requestRPM();
  static unsigned long lastPrint = 0;
  if (millis() - lastPrint > 100) {
    Serial.print("RPM: "); Serial.println(rpm, 0);
    lastPrint = millis();
  }
}

What this version does and does not do

  • Does: reads RPM over CAN as fast as the ECU answers and prints it to the Serial Monitor.

  • Does not yet: draw on the screen, read speed, fuel trims, or codes, or play the greeting. Those come next, one piece at a time.

  • First test: with the car running, open Serial Monitor at 115200 baud. You should see RPM near idle (about 600 to 800). If you see nothing, the pins, wiring, or CAN speed are the first things to check.
